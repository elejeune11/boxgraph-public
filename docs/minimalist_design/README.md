# BoxGraph: the minimalist design

The essentials only: what we are building and why, and the three things it
is made of. Documents 1 to 4 deliberately say nothing about how the code is
written or how agents do the reading. Those are choices that will change as
tools improve; what is there should not. Document 5 is the exception: the
few requirements on how it is built that we hold fixed.

## In one paragraph

A literature review today is prose. A reader can't trace a number to the
page it came from, can't tell whether a paper's results follow from its own
equations, and rarely learns where papers contradict each other. We are
building a literature review that is **executable**: every value traced to
its source, every model rebuilt and run on the paper's own inputs, every
claimed relation between models tested, and every disagreement recorded as
a result. Whoever does the reading, the record makes the reading
checkable.

## Three names

- **BoxGraph** defines the kind of record: what can be written down about a
  paper, and the checks on it. It is the same in every field.
- **ModelAtlas** is every model taken in, each as its paper states it,
  joined to the others by relations that have been checked.
- **The Synthesis** is what every paper states, what checks out within each
  paper, and what checks out across papers.
